# Development Guidelines

Act as a **Senior Advisor**, not just an implementation assistant.

Before changing code, first critically evaluate whether a change is actually necessary. Challenge assumptions, identify weaknesses, and recommend improvements when appropriate.

## Project Goal

This project is a **Master’s thesis and research-quality open-source project**. The algorithm should reliably detect FSMs in **real-world Java projects**, not just match specific examples.

Prioritize:

* Generality over example-specific solutions.
* Semantic and structural patterns over hard-coded names or syntax.
* Correctness, robustness, and maintainability.
* Low false positives and false negatives.
* Solutions that generalize across different Java coding styles and architectures.

When a new example fails, **do not immediately add a special case**. First determine what general limitation it reveals and whether the underlying algorithm or abstraction should be improved.

Before implementing a change, consider its impact on existing cases, scalability, and research validity.

The goal is to build a **general-purpose, professional FSM detection algorithm**, not an algorithm optimized to pass individual examples.

## What this project is

SealFSM is a Java 21 static-analysis tool that extracts finite state machines from sealed class hierarchies. It is the implementation component of a master's thesis titled "Automated Extraction of Finite State Machines from Sealed Class Hierarchies in Modern Java: A Static Analysis Approach."

The tool reads Java source code via Spoon, finds sealed type hierarchies, classifies which ones are state machines (rejecting plain sum types), extracts states and transitions, and outputs the FSM as Graphviz DOT and W3C SCXML.

## The thesis distinction — never conflate these

The tool makes two claims of DIFFERENT strength. Every piece of code, output, test, and documentation must keep them separate:

1. **State enumeration is provably complete.** States come from `permits` clauses, which are compiler-checked exhaustive. This is exact. A permitted `enum` contributes its constants as child states — an enum's constants are closed in exactly the way a `permits` clause is, so this stays exact rather than becoming heuristic.
2. **Transition extraction is approximate.** Transitions are recovered via intra-procedural data-flow analysis. This is empirical and reported with precision/recall.

Unresolved transitions are FIRST-CLASS — they are recorded (dashed red in DOT, XML comment in SCXML), never silently dropped. This is a design invariant, not a convenience.

## Build and run

```bash
mvn package                    # build fat jar
mvn test                       # run all tests
mvn compile                    # compile only (for debug tools)

# One command: clean build, run every examples/<name> into its own
# out/<name>/, render every .dot to .png (needs Graphviz `dot` on PATH),
# and save everything printed to out/results.txt (-IncludeDiagnostics to
# also capture [INFO]/[WARN] lines, off by default)
scripts\build-run-render.ps1
scripts\build-run-render.ps1 -Example traffic -SkipBuild   # one example, reuse the jar

# CLI, by hand
java -jar target/sealfsm.jar --src examples/traffic --out out/traffic

# --classpath narrows what noClasspath has to GUESS (F23). It is not an
# alternative to noClasspath, which stays on: no realistic invocation supplies
# every transitive dependency, and it is what lets an unresolvable type degrade
# into a guessed qualified name instead of aborting the build.
java -jar target/sealfsm.jar --src src/main/java --classpath "libs/a.jar;libs/b.jar" --out out/x

# --explain prints, for every REJECTED sealed root, each classifier predicate and
# why it failed. Printed regardless of --quiet: it was explicitly asked for, and
# a rejection otherwise names only the predicate that ran LAST.
java -jar target/sealfsm.jar --src examples/shape --out out/shape --explain

# Faithfulness instrument: run the CLI over every fixture into its own tree, so a
# refactor is checked by a plain diff. .dot and .scxml are the contract;
# summary.txt is captured beside them and normalised for the output path only.
bash scripts/capture-golden.sh target/golden-pre
#   ...change something...
mvn package -DskipTests && bash scripts/capture-golden.sh target/golden-post
diff -r target/golden-pre target/golden-post          # must be empty, or explained

# Debug tools
java -cp target/classes io.sealfsm.DebugHarness examples/traffic
java -cp target/classes io.sealfsm.DebugAst examples/door --returns

# Render diagram
dot -Tpng out/traffic/TrafficLight.dot -o TrafficLight.png
```

**Never run `--src examples --out out` as one combined invocation** (and never
give a new `examples/<name>/` fixture a Java package another example already
uses). Every example directory uses a distinct package for exactly this
reason: two top-level types sharing one package makes Spoon refuse to build
the model at all (`ModelBuildingException: The type X is already defined`),
and even past that, `Main` names output files after the *machine*, not the
source directory — a flat `--out` lets a second same-named machine (e.g. two
different `DhcpState` fixtures) silently overwrite the first's `.dot`, no
warning. `scripts\build-run-render.ps1` runs each example into its own
`out/<name>/` and sidesteps both failure modes; use it (or per-directory `--src`
calls) instead of the combined form.

## Architecture — the pipeline

```
Java source → Spoon parser → CtModel
  → SealedHierarchyDetector (finds sealed roots, filters nested)
  → StateMachineClassifier (FSM or sum type? polymorphic/centralized?)
      ↳ decides over DispatchFinder.Sites — the SINGLE recognition surface
      ↳ a root rejected by ABSTENTION re-offers its nested sealed
        subtypes as roots (Analyzer's worklist) — a VETOED one does not
      ↳ detect/dispatch/  — the two axes, kept apart:
          DispatchFinder    WHERE the state is discriminated (the locus) and
                            into which arms. Asks nothing about the commit.
          CommitClassifier  HOW the chosen successor is installed. One rule,
                            asked at any locus. This is the precision guard.
          MutatorRecognizer is `ctx.setState(x)` a commit? (structural, F22)
          CompositionVeto   sibling-vs-nested; shared by every acceptance path
      ↳ DispatchCommitDetector   = the COMPOSITION of the two: locus, then
        commit, then veto. What the extractor and the tests consume.
      ↳ CarrierTransitionDetector (carrier successors; owns the veto's evidence)
  → StateExtractor (permits → State IR, exact)
  → TransitionExtractor + TransitionResolver (data-flow → Transition IR, approximate)
  → Analyzer (orchestrates above + initial-state heuristic)
  → DotSerializer / ScxmlSerializer → .dot / .scxml
```

## Examples (also regression fixtures)

- `examples/traffic/` — POLYMORPHIC: sealed `TrafficLight permits Red, Green, Yellow` with `next()` methods. 3 states, 3 resolved transitions, initial=Red.
- `examples/door/` — CENTRALIZED_DISPATCH: sealed `Door permits Open, Closed, Locked` with `DoorMachine.transition(Door, Event)` pattern-matching switch. Exercises guarded ternary, `return current` self-loop, type-pattern from-states. 3 states, 5 resolved transitions, initial=Closed.
- `examples/tcp/` — POLYMORPHIC dispatch, POLY_CARRIER commit: sealed `TcpState` permits the 11 RFC 9293 states, each overriding `Transition on(Event)` where the successor is an *argument* to `Transition.to(...)` and `Transition.ignore(this)` is a self-loop. 11 states, 44 resolved transitions, initial=Closed. `tcp.Event` is Σ and must stay unrecognized.

**The commit-form family** — four fixtures holding the ENCODING fixed (one switch over the state type) and varying only where that switch is hosted and how its result is installed. Recognising only the first was the false-negative that the commit axis closes.

- `examples/http2-stream-claude/` — CENTRALIZED_DISPATCH / VALUE_RETURN: `StreamStateMachine.next(state, event)` is a static pure function outside the hierarchy, `return switch (state) { case Idle s -> fromIdle(s, event); ... }` delegating to per-state helpers. 7 states, Σ = 8 composed symbols (`Send.HEADERS`…), 20/20 resolved, `Closed` terminal. Exercises **type** patterns (`case Idle s`), F3 delegation folding, and **component dispatch** (`case Send(Signal s) -> switch (s)`).
- `examples/http2-stream-gemini/` — CENTRALIZED_DISPATCH / FIELD_MUTATION: the SAME RFC 9113 machine as `this.currentState = switch (this.currentState) {...}`. The host takes no hierarchy-typed parameter, so the signature-based recognizer never saw it. 7 states, Σ = 8 flat enum constants, 20/20 resolved, `Closed` terminal. Exercises **record** patterns (`case Idle()`) and multi-label arms.

**These two are the same automaton written twice, independently, in different idioms** — `ExtractionIntegrationTest.bothHttp2ModelsRecoverTheSameMachine` requires identical states, |Σ|, initial state and (modulo input spelling) transition relation. Two source spellings, one answer, is the strongest correctness signal in the corpus short of hand-written ground truth; keep it passing. It is also why component labels matter: while an edge carried the event *family* (`Send`) instead of the input (`Send.HEADERS`), this pair reported 18 edges against 20 and the gap looked like a recall difference between commit forms.
- `examples/barefield/` — CENTRALIZED_DISPATCH / FIELD_MUTATION with the `this.` omitted: `state = switch (state) {...}; return state;`. 3 states, 4/4, `Fired` terminal. Pins that recognition keys off the resolved TYPE of the assignment target, never the spelling.
- `examples/accumulator/` — CENTRALIZED_DISPATCH / LOCAL_ACCUMULATOR: `Phase next = switch (phase) {...}`, whose arms compute the successor by assigning a *second* local on several branches. 4 states, 4/5 (one out-of-budget delegation stays UNRESOLVED). This is the F1 trap in both directions: a fabricated unguarded self-loop from the local's declared type, or a real target lost to collapsing the branch assignments.
- `examples/valueforms/` — SUCCESSOR FORMS: sealed `Signal permits Idle, Armed, Firing, Phase` holds the encoding fixed and varies only how each successor is *written* — construction, a concrete-typed singleton, a **root-typed** singleton (resolvable only via its initializer), enum constants (`Phase` is a permitted enum), a local, `this`, and a helper call that must stay UNRESOLVED. 6 states (the enum contributes RAMP/PEAK), 9/10 resolved.
- `examples/shape/` — NEGATIVE CONTROL: sealed `Shape permits Circle, Square, Triangle` with `area()` returning `double`. Must be REJECTED — no method returns the hierarchy type.
- `examples/treebuilder/` — NEGATIVE CONTROL for the sibling-vs-nested guard, on **both** acceptance paths: sealed `Expr permits Lit, Neg, Add` with per-subtype `Rewrite simplify()` (structurally identical to `examples/tcp`) *and* `CentralRewriter.fold(Expr)`, a centralized `return switch (e)` (structurally identical to `examples/door`). Must be REJECTED either way, because `new Add(fold(a.left()), fold(a.right()))` nests H inside a bigger H.
- `examples/hiddenreturns/` — **F18 FIXTURE**: sealed `Pump permits Idle, Priming, Running, Halted`, dispatched by `PumpController.transition` delegating to one helper per state. The encoding is held fixed (CENTRALIZED_DISPATCH / VALUE_RETURN, the shape F3 exists for) and only one thing varies — which construct the helper's `return` sits inside. `fromIdle` returns from a `switch` **statement**, the ordinary pre-arrow spelling of a per-event table and the shape the fold could not summarise at all; its three edges come back carrying their Σ labels, which is the proof the fold reuses the real walker rather than a collector with no notion of a case label. `fromPriming` returns from a `try` and again from its `catch` — the classic error transition, which must arrive under the exceptional guard, not unconditionally. `fromRunning` is the sharp one and the reason this was a **soundness** bug: one return inside a loop, one after it, so a summariser that folds whatever it reached and reads a non-empty result as complete publishes `Running → Running` **resolved** and drops `Running → Halted` — a real transition gone with **no unresolved marker**, behind a clean-looking n/n. `fromHalted` is the **negative control and the standing probe**: its only return is inside a `synchronized` block, which the walker does not descend, so it must stay **UNRESOLVED**. `synchronized` is not special — the point is that the completeness test asks what the walk *actually reached*, not whether the body matched a list of constructs someone remembered to extend; teach the walker about it and the assertion fails loudly and a new probe is chosen, which is the correct outcome. 4 states, 9 transitions, 8/9 resolved, initial=`Idle`. Compiled by `javac` as part of being a fixture.
- `examples/nonreturning/` — F9 FIXTURE **and its negative control**: sealed `Latch permits Idle, Armed, Fired`, dispatched from `LatchMachine.step`. Every producer returns `Latch` and every one yields an empty return-summary to a walker that stops at the first construct it does not model, so they are indistinguishable by the summary alone and only the REASON the summary is empty separates them. `reject` has none — provably always throws, so its three arms contribute **no edge**. `defer` returns from inside a `synchronized` block the walker does not descend, so it can produce a state the analysis cannot see and its arm must stay **UNRESOLVED**; dropping that one is the false-drop F9 must never cause, and it is the reason the fixture pairs them. `escalate` returns from inside a `switch`: it *was* that control, and **F18** turned it into the positive case — the fold now runs the ordinary walker over a callee body, so the arm resolves. It stays because it is also the **context-sensitivity control**: `escalate` re-switches on the state, and its `default:` arm cannot run at the only call site, which has already matched `Idle`. Folding it without that reasoning publishes a second edge sourced at `<unknown>`, an origin invented out of a context the walk was holding all along. It also carries **F11**: `case HOLD -> Objects.requireNonNull(current)` calls a JDK method, so Spoon supplies a reflective *shadow* declaration whose body is an empty stub. That body has no `return` for the same reason it has nothing at all — it was never parsed — and F9 read the emptiness as proof and deleted the edge. The rule may only be applied to a body the analysis actually **read**. 3 states, 6 transitions, 4/6 resolved, `Fired` terminal.
- `examples/lcp_automation/` — **RFC 1661 LCP**, the densest fixture and the one F10/F11/F12 were all found on: sealed `LcpState` permits the 10 §4.1 states, dispatched by `PppLcpStateMachine.transition` delegating to ten per-state handlers. 13 events × 10 states = 130 cells, +14 guard splits = 144 arms, of which 31 `throw` → **113 transitions, 113/113 resolved**, 46 of them self-loops (the RFC writes "ignore this event here" as an explicit stay-put cell). Σ = 13. Initial = `Initial`, recovered only by the weakest heuristic — every state including `Initial` has incoming edges, so the structural rule has no candidate. **Every** edge arrives through F3 delegation folding, which makes this the hardest stress test of that path in the corpus. LLM-generated from the RFC and left unedited except for the RXR event, which was missing and was added by hand (noted in the file).
- `examples/lcp_automation_chatgpt/` — **RFC 1661 LCP, written a SECOND time and independently**, and the corpus's strongest correctness signal after the http2 pair. Same specification as `examples/lcp_automation`, same 10 §4.1 states, but committed through a **carrier**: the centralized dispatch returns a wrapper type with exactly one `LcpState`-typed component rather than returning the state itself, and every arm delegates to a per-state helper (all 111 edges arrive through the bounded inter-procedural fold, which the diagnostic reports). 10 states, Σ = 16 (it spells RFC 1661's ± distinctions as separate constants — `RCR_PLUS`/`RCR_MINUS`, `RXJ_PLUS`/`RXJ_MINUS`, `TO_PLUS`/`TO_MINUS` — where `lcp_automation` splits them with guards), **111/111 resolved**, initial=`Initial`, plus **49 undefined cells suppressed by F9** and reported as a diagnostic. Two independent implementations of one specification, under two different commit forms, recovering essentially the same relation (111 vs 113) is a stronger claim than any single fixture can make.
  Until the dispatch and commit axes were separated it was **rejected outright** — "no transition producer found", 0 machines — because the carrier recognizer required a per-subtype override and the switch recognizer required the commit to BE a hierarchy value, so a centralized table returning a wrapper satisfied both halves of a valid pair and matched neither. It is also the corpus-scale confirmation of `examples/throwcarrier`'s prediction that the fabrication would be "roughly forty on a specification the size of RFC 1661's LCP": it is 49, one resolved self-loop per undefined cell, and every one of them would have inflated both halves of the recall figure.
- `examples/guardforms/` — **GUARD FORMS**, the axis orthogonal to encoding / successor form / commit form: how a `when` clause is *spelled*. Two states, one dispatch, twenty arms varying only the guard expression — bare invocation, unary, binary, `&&`, `||`, boxed `Boolean`, pattern-binding read, `instanceof`, ternary, array access, negated binary, static call, call chain, library static, a **switch-expression guard**, redundant parens, deep compound, a lambda inside the guard, a `(Boolean)` cast, and a nested record pattern. 2 states, 22/22. Only 7 of the 20 take Spoon's supported `getGuard()` path; the other 13 are recovered from the arm body, and the split is invisible from the source — which is why they are enumerated rather than assumed. Three were found losing their guard *only* by writing this table out: a `Boolean`-typed guard failing a check written for the primitive, a cast (not its own node in Spoon, so it reported the invocation's `Object` type), and a switch-expression guard whose five-line text reached the DOT label with newlines intact — Graphviz accepts that, so it failed silently. `Trigger.Inner` is deliberately **not** a `Trigger`: a permitted subtype inside another's component list makes Σ recursive, and the classifier then reports the event alphabet itself as a second machine.
- `examples/plumbing/` — **F10 FIXTURE**: sealed `Conveyor permits Stopped, Running, Jammed`, dispatched twice (VALUE_RETURN and FIELD_MUTATION) with each host buried in the bookkeeping real code contains — a `requireNonNull` prelude, an in-model `identity(current)` call, an audit call, a log line, a counter bump. None installs a successor, so none may be an edge. 3 states, 6/6. The sharpest statement is `identity(current)`: in-model, hierarchy-typed and trivially summarisable, so F3 *would* fold it to a self-loop — only its statement position rules it out, which is why a hierarchy-type guard alone is not the rule.
- `examples/plumbing-mutation/` — **NEGATIVE CONTROL for F10**: `@Fsm`-marked sealed `Hopper permits Empty, Filling, Full`, committed only through `ctx.setState(...)` — an expression statement that IS the commit. Separate hierarchy because the F2 path runs only as a fallback; beside a VALUE_RETURN machine it never executes and the control would assert nothing. `drive` uses **arrow** arms of a switch *statement* and `pump` **colon** arms, encoding deliberately DISJOINT relations so the two spellings stay separately attributable. 3 states, 6/6. It reports 3 nondeterminism warnings **by design**: mutation-encoding event labelling is future work, so both hosts' edges are eventless and `Empty` really does have two indistinguishable successors *as extracted*. That is an honest reading of what was recovered, not a defect.
- `examples/scopedlocals/` — **F13 FIXTURE**: sealed `Gate permits Shut, Ajar, Wedged`, dispatched by `GateDriver.transition`, whose three arms each declare a local named `next`. That is the ordinary way a per-arm switch is written and legal because Java scopes a local to its block, so these are three distinct variables sharing a spelling. The `Ajar` arm reassigns its `next` (and is the **negative control**: `next` starts as the root-typed selector `current`, so reading it as single-assignment fabricates an unguarded self-loop and loses the `new Wedged()` target — finding F1); the other two do not. The fixture is **one rename away from 5/5 and 4/5** — spelled `nextA`/`next`/`nextC` the same source reports every edge. The `Wedged` arm is where the loss lands: a single-assignment local read from inside a `try`, which the reaching-definitions fallback cannot model, so the degraded read bails to `-> ?` rather than merely relabelling its successor form. 3 states, 5/5, initial=`Shut`.
- `examples/throwguards/` — **F14 FIXTURE**: sealed `Valve permits Charged, Venting, Faulted, Bleeding, Latched, Purging`, dispatched by `ValveController.transition`, whose six arms are all the same statement pair — a rejection test, then a producer. Only whether the rejection branch can complete normally decides if the producer may carry the negated test, and the arms vary exactly that: a bare `throw`, a block *ending* in a throw, an exhaustive `switch` every arm of which throws, and three **negative controls** — a branch that only *contains* a throw (takes it conditionally, so its producer stays unguarded; claiming otherwise fabricates a constraint the source does not impose), an exhaustive switch whose `default` leaves by `break`, and one whose trailing `default:` carries no statements at all. The last two are the sharp ones: their switch is a bare sibling rather than an `if` branch, so misjudging it does not mislabel a guard — the producer below is written off as unreachable and **the edge is deleted**, leaving a clean-looking 5/5 with no unresolved marker. 6 states, 6/6, initial=`Charged`. Every arm is compiled by `javac` as part of being a fixture, which is what makes the reachability claims checkable rather than asserted.
- `examples/rivalseeds/` — **F15 FIXTURE**: three hierarchies in one package, holding everything else fixed (CENTRALIZED_DISPATCH / VALUE_RETURN, strongly connected so the structural rule always abstains) and varying only what the seeded-FIELD rule is handed. `Sluice permits Shut, Flowing, Blocked` has **two drivers seeded differently** — the rival-seed case: nothing in the program says which is the start, so the honest report is a GAP plus a diagnostic naming both candidates. `Damper` is the **negative control for unanimity** — two drivers that AGREE must still answer `Parked`, or "require unanimity" silently becomes "give up whenever a machine is constructed twice". `Ratchet` is the **negative control for `isSelfSingleton`**, and the sharper one: one real driver seeded `Free` beside two flyweight `INSTANCE` constants, which absent the exclusion outvote it so the correct answer is **lost** — the fix for a fabricated claim turning into a dropped one. 3 machines, 22/22. Every file is compiled by `javac` as part of being a fixture.
- `examples/chaindispatch/` — **F17 FIXTURE**: four hierarchies in one package, holding the encoding fixed (CENTRALIZED_DISPATCH, one discrimination of the state per driver) and varying only what the chain rule is handed. `Relay permits Idle, Live, Tripped` is the shape the finding is about — a **field** selector, no hierarchy-typed parameter, no `switch` — which matched no recognizer at all and so lost the whole hierarchy; 3 states, 4/4, FIELD_MUTATION. `Shutter permits Open, Closing, Shut` is the other half: `ShutterLogic.next(Shutter, Command)` was recognised all along by its signature, and every type test was then walked as a **data guard**, so a fully accepted machine reported 5 edges with `<unknown>`/`<entry>` sources and 0 resolved; 3 states, 5/5, VALUE_RETURN. It also carries the three questions a chain asks that a switch never does — a **conjoined** event test (`current instanceof Open && command == LOWER`, where the type test is the arm label and the rest is still Σ), a **residual under negation** (the `Open` link has an extra condition, so `Open` is still reachable below it and keeps its edge under `!extra`; `Closing`, tested bare, is genuinely gone), and a **trailing statement after a closed chain** (`return current;` is reached exactly in the states no link claimed). `Glyph permits Dot, Dash` is the **codomain control**, the `instanceof` spelling of `foreignfold`: the same discrimination assigned to a `String` field, beside a field-mutation machine that IS one, so the declared type of the written field is the only thing separating them. `Tree permits Leaf, Pair` is the **composition control** and the sharper one — unlike `treebuilder` it declares **no methods at all**, so `composesItself` answers false and the distributed recognizer finds nothing, and the shared sibling-vs-nested predicate is the only thing that can reject it; `Pair` is deliberately a class rather than a record, because a `Tree`-typed record component synthesises an accessor returning H that the distributed recognizer reads as a per-state transition method, and the control would pass while testing nothing. `RelayBoard.reset()` is the **two-branch control**, and the one place the fixture records a cost: a single type test that commits contributes **no edge**, so `Tripped → Idle` is a transition the program can make and the tool does not report. The package is deliberately not named `instanceofchain` — guard text is compared as source text, and that name puts the substring `instanceof` inside every qualified name in every guard, which silently defeats the assertion that no type test survived as one. The fixture found that on itself.
- `examples/foreignfold/` — NEGATIVE CONTROL for the widened centralized recognizer: sealed `Mode permits Fast, Slow, Stopped`, a driver holding a `Mode` field, and exhaustive switches over it in **both** accepted commit positions (`return switch` and field assignment) — but folding into `String`/`int`. Must be REJECTED by the commit requirement. Accepting it would report an automaton whose every state has zero transitions.
- `examples/namecollision/` — **NAME-COLLISION FIXTURE**: sealed `Link permits Idle, Legacy.Idle, Phase, Mode`, holding both legal ways two states end up with the same simple name. `Idle` and `Legacy.Idle` are a top-level type beside a nested one — legal even outside a named module, since `permits` only requires the same *package* there and `Legacy` is in it; a cross-package pair (`a.Foo`/`b.Foo`) is the other spelling and is legal inside a named module. `Phase` and `Mode` are two permitted enums that both declare `IDLE`, and since a permitted enum contributes its constants as child states, those are two distinct states spelled identically — the likelier shape by far, because nothing discourages reusing `IDLE`/`ERROR`/`NONE`. 8 states, 12/12. Keyed on simple names it reports **11/11**: the two `UPGRADE` arms encode `Idle → Legacy.Idle` and `Legacy.Idle → Idle`, which collapse to the same `(from, to, event, guard, resolved)` tuple, and the extractor's transition `LinkedHashSet` discards one. A real transition dropped with **no unresolved marker**, behind a clean-looking `n/n` — the one outcome the record-everything invariant forbids. Graphviz hides the rest: node ids are global, so a state declared inside two clusters silently becomes one node in the first, with no warning, and the SCXML emits duplicate `id`s.

## Key implementation details

### StateNaming (model/StateNaming.java)
The single mapping from a state's qualified name to the **id** that names it everywhere downstream — DOT node ids, SCXML `id`/`target`, and both endpoints of every `Transition`.

An id used to be the bare simple name, which is **not** an identity: a `permits` clause may legally name two types sharing one (a nested type beside a top-level one in the same package; two types in different packages inside a named module; two permitted enums declaring the same constant). The consequence was not cosmetic. Two distinct edges between two distinct states became the same `(from, to, event, guard, resolved)` tuple, and the extractor's transition `LinkedHashSet` discarded one — a transition dropped with **no unresolved marker**, reported as a clean `n/n`. `examples/namecollision` is the fixture; it reports 11/11 without this and 12/12 with it.

- **The rule**: an id is the *shortest dot-separated suffix of the qualified name that is unique* among the machine's states. Uncollided states therefore keep their bare simple name, so existing output is byte-identical and only collided states lengthen: `namecollision.Idle` / `Legacy.Idle`, `a.Foo` / `b.Foo`, `Phase.IDLE` / `Mode.IDLE`. A package prefix alone is NOT the rule — the first pair shares a package, and the nest path is what separates them.
- Qualified names are **canonicalised** (`$` → `.`) before anything else. Spoon spells a nested type `Owner$Nested`, so splitting on `.` alone reads that whole tail as the simple name: every nested state in the corpus gets renamed and no nested collision is ever detected. This was found by the test suite, not by inspection.
- The naming must be built **once** and consulted by *every* producer of a state name — `StateExtractor`, `TransitionExtractor` (from-states, `dispatchedStates`), `TransitionResolver` (targets) and `Analyzer` (initial state). Disambiguating ids after the fact cannot work: by then an endpoint reads `"Idle"` and the information that would tell the two apart is gone. This is why `StateExtractor.extract` returns the naming alongside the states rather than letting callers rebuild it — a second construction of the "same" mapping is exactly how the two halves would drift.
- `StateMachine.duplicateStateIds()` is the drift check, reported by `Analyzer` as a WARN. It should always be empty; it exists because the assignment and the extractor are separate code, and a disagreement between them would otherwise be invisible in the output. A diagnostic, not a throw — a wrong diagram on someone's repository is bad, a crash is worse.
- Only STATE names go through it. `TransitionExtractor` derives event symbols, field names and variable names with `getSimpleName()` too, and those must stay untouched.

### SealedHierarchyDetector (detect/SealedHierarchyDetector.java) + the re-offer worklist
A sealed permitted subtype is withheld from the root list because its parent claims it as a **composite state**. That claim is only good if the parent turns out to be a machine — and the detector runs *before* classification, so it cannot know. When the parent was then rejected, the child was lost with it and the only diagnostic named the parent. `sealed interface Message permits Header, Body`, where `Body` is itself a state machine, is an ordinary shape.

- `permittedSealedSubtypes(root)` offers the withheld hierarchies back; `Analyzer` iterates roots as a **worklist** rather than a list, so a rejected root can append to it. An `enum` is never offered — it is not sealed, and its constants are already exact child states.
- **Only an ABSTENTION releases them**, which is why `Classification` now carries a `Rejection` (`NONE` / `ABSTAINED` / `VETOED`) instead of only a reason string. The two rejections mean different things: "no transition producer found" says nothing about a machine declared *inside*, whereas the compositional veto is a verdict about the data type, and a member of a recursive data type is still one.
- The veto exclusion is **not** conservatism for its own sake. The veto is judged against the hierarchy set of whichever root is classified, and a child's set is strictly narrower — so re-offering can make the composition *invisible*. In `examples/nestedroots`, `new Wrap(child)` with `child` typed `Node` nests one hierarchy value inside another as far as `Node` is concerned; judged against `{Branch, Pair, Wrap}` the argument is a foreign type and the same expression reads as a peer production. `Branch` then classifies as POLYMORPHIC — a tree builder reported as an automaton, one level below the veto that caught it. The test asserts `Branch` *would* be accepted, so the control cannot quietly stop testing anything.
- A machine genuinely nested inside a *compositional* hierarchy therefore stays lost. That is a recall gap and a deliberate one: closing it means judging the child against its **widest enclosing** hierarchy, which is a change to the compositional veto itself, not to the worklist.
- `Analyzer` also claims every member of an accepted machine, so a type that is a **state** is never also re-offered as a **root**. Vacuous in the common case; it matters when a sealed type extends two sealed interfaces and only one is a machine.
- `DebugHarness` mirrors the worklist, or the debug view would show a different root set from the one the pipeline classifies.

### SpoonCompat (detect/SpoonCompat.java)
All version-sensitive Spoon calls live here. `isSealed()` checks `ModifierKind.SEALED` with try/catch fallback. `permittedTypes()` uses reflection for `getPermittedTypes()` with a fallback that scans the model for direct subtypes (handles implicit permits).

**F23 — `noClasspath` resolution was unguarded and unreported.** Every model is built with `setNoClasspath(true)`, under which a type Spoon cannot bind does not fail — it reaches the analysis as a reference carrying a *guessed* qualified name. Every recognizer decides membership with `hierarchy.contains(ref.getQualifiedName())` against a set `StateMachineClassifier.collectHierarchy` builds from **resolved declarations only**, so an unresolved reference always answers "not in the hierarchy" — the identical answer a genuinely foreign type gives. Nothing downstream could separate them, so a result thinned by unreadable input was published as a finding about the program. Withholding one state file from `examples/traffic` takes it from 3/3 to 1/2, and withholding `examples/door`'s three state files gives 0/5 plus six nondeterminism warnings about a state `<unknown>` — in both cases with **no diagnostic mentioning resolution at all**. Worse than silence, the centralized case was *misattributed*: each arm reported "could not determine source state for a switch case", blaming the switch-arm handling for an input problem, which in a thesis reporting recall stratified by idiom is a wrong number in the table rather than a confusing message.

- `isUnresolved(ref)` is the single predicate, and it keys on **`getTypeDeclaration() == null`** — measured, not assumed, to be exactly the discriminator wanted: a source type and a classpath type both answer non-null (the latter a shadow, whose qualified name is still authoritative — F11), and only a genuinely unbound reference answers null. Primitives, `void`, the null literal's type, type parameters and wildcards carry no declaration for reasons that are not failures and are excluded; an array is resolved exactly when its component type is.
- **An IMPLICIT reference is excluded, and that exclusion is what makes the diagnostic usable rather than noise.** Spoon synthesises a `record`'s accessors, and the generated body's implicit `this` carries a type reference built from the bare simple name with no package, so it never binds — one per record component. Without the exclusion four fully-readable fixtures reported resolution failures (`Timeout`, `Pending`, `Error`, `Boxed`…) and three correctly-rejected event alphabets were told their rejection might be one. It is also right on the merits: an implicit reference was never *written*, so it is not evidence that the source mentions an unreadable type, and a genuinely missing type is always referred to explicitly somewhere too. `isImplicit()` is the signal and **source position is not**, though F11 uses position for the analogous shadow test — a type pattern's reference (`case Shut s`) reports no valid position while being a real, explicitly written failure, so a position filter would discard the true positives along with the noise.
- **No verdict keys on a simple name, deliberately** — and on `master` no verdict changed at all. Membership still answers "no" for an unresolved reference whose spelling nothing vouches for. Promoting one on a simple-name match would fabricate a *resolved* edge to a state the analysis never established — the one failure mode the soundness invariant forbids outright — and a simple name is not an identity (`examples/namecollision`), while Spoon's guesses are not even stable: one unresolvable `Signal` was observed reaching the model as both `pkg.Signal` and a bare `Signal` within a single build. So the failure is *recorded*, exactly the trade the tool already makes for an unresolved successor. The whole corpus is byte-identical across this change. **On this branch one class of reference IS promoted** — the one the `permits` clause itself wrote, which is a compiler-checked membership statement rather than a resemblance; see *Membership recovery* below.
- `unresolvedPermittedTypes(root)` is the severe case, because it lands on the claim the tool makes **exactly**. `StateExtractor` reads states from the permits *references*, so such a state is still enumerated by name — but its declaration was never read, so a sealed or `enum` member's children are silently absent, and on `master` it is missing from every membership set, which costs every edge mentioning it. This branch closes the membership half only — see below.

### TypeResolutionAudit (detect/TypeResolutionAudit.java)
One model-wide pass collecting every distinct unresolved type name, built once per model in `Analyzer.analyze` and consulted per root — rebuilding it per candidate would repeat the traversal for an answer that cannot vary. Reporting is stratified by whether the failure can touch a hierarchy, because a severity that does not discriminate is one a reader learns to ignore:

- **model level, INFO** — a count plus a sample. Run over a real project with `--src src/main/java`, every third-party type is unresolved and almost none of it matters; a WARN there would be noise.
- **per hierarchy, WARN** — an unresolved *permitted subtype*, or an unresolved name sharing a simple name with a member.
- **on a rejection, WARN** — the headline: "no transition producer found" and "I could not resolve the types" were previously the same output. A rejected root whose vicinity failed to resolve now says so explicitly.

`resembling()` is the one place a simple name is consulted, and it selects the **text of a diagnostic** — never an edge, a state or a classification — which is what keeps it clear of the rule that no analysis decision keys on a name (F22). The message is hedged accordingly: a match does not prove the reference *is* that member.

### Membership recovery for unread permitted members (BRANCH `unresolved-member-recovery`)

**This section describes a change that is NOT on `master`.** It resolves a
disagreement F23 documented but deliberately left standing: `StateExtractor` and
`StateMachineClassifier.collectHierarchy` answer "what is in this hierarchy?"
from different sources. States come from the `permits` *references* (no
declaration needed); membership came from *resolved declarations* only. Withhold
`examples/traffic/Yellow.java` and the tool enumerates 3 states while no
recognizer will admit that any of them is `Yellow` — `Green.next()`, fully
readable and returning `new Yellow()`, fails `hierarchy.contains(...)` and its
edge goes unresolved. 3 states, 1/2, and one of them is a state no edge can
touch.

- `StateMachineClassifier.hierarchyQualifiedNames` is now the resolved member
  names ∪ `unresolvedMemberNames(root)`, the names carried by permits references
  that did not resolve. `hierarchyTypes` is unchanged and stays resolved-only — a
  declaration that was never read has no body to walk. Both the recovery and the
  resolution diagnostic ask the same helper, so the set warned about and the set
  admitted cannot drift.
- **Why this is not the simple-name promotion F23 forbids.** `permits X` is the
  compiler-checked statement that X is a member — the same statement the *exact*
  state enumeration already rests on, which is why the state is in the output at
  all. Only the **spelling** Spoon assigns the reference is a guess; membership is
  not. No resemblance is consulted anywhere: a use site joins the hierarchy only
  when Spoon spelled it with the byte-identical qualified name, which is the test
  every resolved member already passes. `TypeResolutionAudit.resembling` stays
  what it was — diagnostic text, never a decision.
- **The residual risk, MEASURED rather than argued** — `src/test/resources/unreadmember/`,
  three variants of one hierarchy differing by a single import line. The worry was
  that a *wrong* guess (an unreadable import making `p.Amber` the guess for a
  `q.Amber`) would admit a foreign type as a state and publish a **resolved** edge
  to it, which is a fabrication. It is **not constructible**, and the reason is
  structural: `permits` requires the same package outside a named module, so the
  only way a simple name there can denote a foreign type is an explicit
  single-type import — and Spoon honours it.

  | variant | Spoon's guess for `new Amber()` | admitted | outcome |
  |---|---|---|---|
  | `samepkg/` — bare, same package | `samepkg.Amber` | yes | edge recovered; the intended case |
  | `explicitimport/` — `import ext.Amber;` | `ext.Amber` | **no** | edge stays unresolved — **the fabrication control** |
  | `wildcardimport/` — `import ext.*;` | bare `Amber`, no package | **no** | edge stays unresolved |

  `wildcardimport` is the opposite error and a real **recall gap**: JLS §7.5.2 makes
  the same-package type shadow a wildcard import, so the reference *is* the state
  and the edge is real — Spoon simply degrades the guess to a bare name and nothing
  matches. Recovery is partial by construction, in that exact way. The same
  instability shows at corpus scale: `examples/namecollision` minus `Legacy.java`
  reaches one model as `namecollision.Legacy$Idle`, `namecollision.Legacy` **and** a
  bare `Legacy.Idle` at once, pinned as a standing probe. These inputs deliberately
  do not compile, which is why they live in test resources and not in `examples/`.
- **`Analyzer.recordUnreadStateGaps` is the other half, and is not separable from
  it.** Recovery buys the edges that *mention* an unread state, never the ones it
  *produces* — that producer is in the file that was not read. Under
  CENTRALIZED_DISPATCH that costs nothing (the state files are data), but under
  POLYMORPHIC it is the state's whole outbound relation, so `traffic` minus
  `Yellow.java` would otherwise report **2/2**: a perfect score on a machine
  missing a third of its relation, a dropped transition behind a clean-looking
  n/n, which is the one outcome the record-everything invariant forbids by name.
  Every unread state that **no dispatch examined** therefore carries an explicit
  unresolved outgoing edge, and `traffic` reports 2/3 — one recovered edge, one
  visible gap. Eligibility is `dispatchedStates`, deliberately the same signal
  `markTerminalStates` already trusts for the same distinction rather than a
  second notion of it. The residual is reported, not hidden: a state a centralized
  dispatch matched, whose unread file *also* declared a producer of its own, gets
  no marker — nothing in the readable source separates that from a state whose
  file holds only data.
- **A recovered edge is separable from a proven one, because the SCORE cannot tell
  them apart.** This is what makes the branch usable as a thesis instrument rather
  than merely correct. `door` minus its three state files reports **5/5** — the
  exact relation — and a 5/5 read from complete source is a strictly stronger
  claim, yet nothing in the number says so. So the weaker evidence is carried in
  the model: `State.isDeclarationUnread()` flags a state enumerated from a permits
  reference whose declaration was never read, and
  `StateMachine.transitionsViaUnreadDeclaration()` counts the edges touching one
  (derived, so it cannot drift from the flags). The count reaches the extraction
  diagnostic, DOT draws such a state **dotted amber** (dotted, not dashed —
  dashed already means "unresolved edge" and these are different claims), SCXML
  carries a comment inside the `<state>`, and `Main` prints a footnote under the
  table **regardless of `--quiet`**, because it qualifies the numbers directly
  above rather than being a diagnostic about them. On the corpus every flag is
  false and every count is zero, so all of it is invisible on well-formed input.
  Door's honest report is "5/5, and all five rest on guessed names"; namecollision's
  is "12/12, of which 5".
- **Measured, on the three shapes that exist.** `door` minus its 3 state files:
  0/5 → **5/5**, relation byte-identical to the whole model, no arm blamed for an
  input problem, no gap fabricated. `namecollision` minus `Legacy.java`: **12/12**,
  identical relation, the `$`-spelled nested id preserved. `traffic` minus
  `Yellow.java`: 1/2 → **2/3**. The full corpus (every `.dot`, `.scxml` and summary
  line, all 40 examples) is **byte-identical** to `master` — no fixture has an
  unresolved member, which is also why no fixture can pin this and the tests build
  partial models instead.
- **The standing argument against merging**, recorded so it is not re-litigated
  from scratch. It is *not* the soundness worry — that was measured above and does
  not reproduce. It is that the triggering condition is an **input error**, not a
  Java idiom: F1–F22 are all "the algorithm mishandled legal Java", whereas this is
  "the tool was pointed at incomplete source", and every number in the validation
  chapter comes from complete source sets, so merging moves no reported result. The
  trigger that would change it: if harvesting real GitHub projects routinely hits
  multi-source-root layouts, partial source sets stop being an error and become
  normal — at which point the better fix is source-root auto-discovery in `Main`
  (`--src <project-root>` finding every `src/main/java`), which removes the cause
  instead of compensating for it, and leaves this recovery for the case
  auto-discovery cannot reach: a hierarchy genuinely unobtainable (split across a
  module boundary, generated, or only present in a dependency).

### detect/dispatch/ — the two axes, kept apart

Four recognizers each used to hard-code a **pair** of independent properties, and the pairing was invisible because it read as one predicate:

```
CarrierTransitionDetector          = per-subtype override ∧ carrier return
DispatchCommitDetector             = switch over H        ∧ {return, field, local}
findCentralizedTransitionMethods   = switch over H        ∧ return ∧ H-typed parameter
findFunctionalTransitionCallables  = lambda selector      ∧ return
```

Fusing them makes valid combinations **unreachable by construction**, and the gap was not hypothetical: a centralized table whose arms return a carrier wrapping the next state satisfies both halves of a valid pair and matched no recognizer — the carrier one demands a per-subtype override, the switch one demands the commit BE a hierarchy value. `examples/lcp_automation_chatgpt`, a complete RFC 1661 LCP machine, was reported as *not a state machine at all* for exactly that reason.

- **`DispatchFinder`** answers only the first axis: *where is the state discriminated, and into which arms?* Five discovery routes (`overrides`, `carriers`, `centralized`, `producers`, `functional`), one return type. The routes are kept apart because they are not interchangeable to a **reader** — "4 per-state transition methods" and "2 centralized functions committing via FIELD_MUTATION" are different reports of different evidence, and the classification reason names which — while `all()` is the view the walker wants. **The finders wrap the existing recognizers rather than reimplementing them**: what a per-state transition method is, and what a discrimination is, are settled questions with fixtures behind them, and a second implementation would be a second notion.
- **`CommitClassifier`** answers the second: *how is the chosen successor installed?* One rule, asked at any locus. This is where the precision lives — a transition switch and an exhaustive fold are identical **at the discrimination**, so only the codomain separates `state = switch (state)` from `label = switch (state)`. `carrierComponentOf(R, H)` returns R's single hierarchy-typed component (a non-static field, so records and plain classes are covered without depending on Spoon's record API); it declines when R is itself in H, when R was never read (F11 — an empty field list on an unread declaration is evidence of nothing), and when R has **several** such slots (undecidable; picking one by field order would fabricate a resolved edge).
- **`MutatorRecognizer`** answers whether `ctx.setState(x)` is a commit channel — structurally, and nothing in it keys on a name (F22). Exactly one parameter typed with the hierarchy **root**, whose value is what the body installs into an H-typed field. Both clauses are load-bearing: without the second, `void restart(Vent previous) { audit(previous); this.state = new Sealed(); }` is admitted exactly as the old word list admitted it, and its parameter is the state being *left*; without "root", a child hierarchy's mutator makes its parent look like a machine (`examples/nestedroots`).
- **`CompositionVeto`** owns the sibling-vs-nested predicate and the F20 helper family it is written in terms of. It lives here because it belongs to no single locus: every acceptance path must apply the *same* guard, or a tree rewrite spelled with `switch` and the same rewrite spelled with `instanceof` get different verdicts.
- **`DispatchCommitDetector` is now the COMPOSITION** — locus, then commit, then veto, in that order. That is what the extractor and the tests consume, and its behaviour is unchanged by the split.

`DispatchSite.node` is the discrimination itself, never the host body: a field-mutation host ends with `return this.state;`, and walking the body reads that as a producer with no attributable source. `DispatchArm.fromSimpleName` is `null` for "reached in more than one state, or in one not determined" — never a stand-in for the first state we thought of — and a type test that SELECTS the state belongs there rather than in `guard` (F17).

### StateMachineClassifier (detect/StateMachineClassifier.java)
`Classification` carries a `Rejection` alongside the reason text: `ABSTAINED` ("no transition producer found") versus `VETOED` (the compositional veto). Only the second is a verdict about the hierarchy's members, and the difference is what decides whether a rejected root releases its nested sealed subtypes — see the re-offer worklist above. Do not collapse them back to a reason string; a caller comparing that string is a caller that breaks when the wording changes.

`classify` and `detectEncoding` decide over `DispatchFinder.Sites`; the classifier no longer knows how a locus is found, only that some site's arms commit a hierarchy value. `classify(root, model, Consumer<String> trace)` is the `--explain` overload — a **side channel on the real decision procedure**, not a second procedure that re-derives the verdict for display, because a report that can disagree with the decision it explains is worse than no report. Only rejections are traced: an acceptance already names the predicate that carried it, while a rejection names only the predicate that ran last.

`centralizedReason` counts **distinct hosts**, not the sum of the two recognizers' findings. The signature-based recognizer and `DispatchCommitDetector` legitimately overlap — an `H transition(H, Event)` whose body is `return switch (current)` is seen by both — so summing them reported `examples/door`, which has exactly one transition function, as two. It keys on `declaringType#signature`, the same key the extractor dedups on, so the reported number and the walked set cannot drift apart.

Contains shared static helpers reused by the extractor:
- `findDistributedTransitionMethods(root)` — methods ON the hierarchy returning hierarchy type
- `findCentralizedTransitionMethods(root, model)` — methods OUTSIDE the hierarchy that **produce** a hierarchy value and **examine** one (see F19 below)
- `hierarchyQualifiedNames(root)` — all qualified names in the hierarchy
- `hierarchyTypes(root)` — all CtType objects in the hierarchy

**F19 — the state is an input however it arrives; a parameter is only one spelling.** `findCentralizedTransitionMethods` required a hierarchy-typed **parameter**, which admits `H transition(H current, Event e)` and nothing else. A driver that holds its own state spells the same function `H step(Event e)` — H out, no H in — and matched no recognizer at all. Whether such a machine was recovered then came down to `DispatchCommitDetector` incidentally finding a commit at the discrimination, and that detector consults only the switch's *immediate* syntactic context: so `return switch (state)` survived, while a `switch` **statement** whose arms return — the ordinary pre-arrow spelling of a per-event table, the same shape `examples/hiddenreturns` pins one level down — was **lost outright with its whole hierarchy**.

- The parameter is replaced by the property it was standing in for, asked directly: `DispatchCommitDetector.discriminatesState(host, H, rootQn)`. The two disjuncts are the two ways a method can be handed the state — as an argument, or by reading a field it then discriminates. The predicate reuses `dispatchesOnHierarchy` and `chainOf` rather than re-deriving them, for the standing reason: a recognizer and an extractor with two notions of "discrimination" would disagree into an edge attributed to a state the classifier never admitted.
- **"Returns H" cannot be the whole rule.** For a value-returning host the codomain test *is* the commit test, so dropping the parameter with nothing in its place leaves no guard at all: every factory (`static Bolt factoryOpen()`) and every accessor (`Relay state()`) in the model is admitted, and the extractor walks each as a standalone dispatch. Ablated on the corpus, that reports `examples/dhcp-client-claude` as **0/1** instead of 20/20 and turns `chaindispatch.Tree`, a negative control, into an accepted machine — because the newly admitted accessors also enter the F3 helper-caller set and displace the real transition function. The commit check carries the *codomain* load; it cannot carry the *input* load, and only the discrimination can.
- **The second failure was a wrong number, not a missing machine, and it is the one to watch for.** `interproceduralHelperSignatures` derives the F3 helper set from the caller side of this same list. An unrecognised driver is not a caller, so its per-state helpers were extracted a *second* time standalone with `from == null` — one fabricated `<entry> → ?` per input symbol, on top of a relation that was already complete and fully resolved. `examples/statefuldriver`'s `Pump` reported **9/12**.
- **The parameter keeps a job — it stops being a recognition test and becomes a statement about SCOPE**, and `TransitionExtractor.extract` reads it as one. A host **handed** the state computes a successor from it end to end, so its whole body is the transition relation: that is what makes `chaindispatch.ShutterLogic`'s `return current;` *after* its chain a real self-loop on the states no link claimed. A host that only **returns** H read the state out of a field, and its body is plumbing around a dispatch. So where a producer already identified the discrimination and its real commit, that producer owns the walk. Ablating this rule alone reports `barefield` and `http2-stream-gemini` as 0/1 and corrupts their commit axis to `FIELD_MUTATION,VALUE_RETURN` — the trailing `return this.state;` read as a successor, and the machine counted under a commit form it does not use.

### DispatchCommitDetector (detect/DispatchCommitDetector.java)
Recognizes centralized dispatch **by the discrimination, not by the host's signature**. Scans every `CtSwitch`/`CtSwitchExpression` and every `instanceof` chain in the model, keeps those whose selector type is in H, and classifies what happens to the result.

- `find(root, model)` → `List<Producer(host, dispatch, CommitForm, selector)>`. The `dispatch` field is the discrimination node itself — the switch, or the head `CtIf` of a chain — and the extractor walks **exactly that node**, never the host body. The field-mutation host ends with `return this.currentState;`, and walking the body would read that trailing return as a producer with no attributable source — a fictitious unresolved edge manufactured out of plumbing.
- **F17 — the switch is one spelling of the discrimination, not the discrimination.** Keying on `CtSwitch` confused a syntactic construct with the semantic notion: what makes a dispatch a dispatch is that the selector's *dynamic type* is discriminated across H and each branch commits a successor, and `if (state instanceof Initial) ... else if (state instanceof Closed) ...` is exactly that, spelled with `if`. A chain in a **named method** matched nothing — no switch for this detector, no H-typed parameter for `findCentralizedTransitionMethods`, not on the hierarchy for the distributed one — and that is the dominant dispatch shape in Java written before pattern-matching switch, i.e. most Java. A chain is admitted on precisely the switch's terms (H selector, H commit, no nesting); nothing about the commit requirement is relaxed for it, so `if (s instanceof Circle) return "circle";` is rejected by the same codomain test that rejects `label = switch (state)`.
  - Two requirements are chain-specific, both because an `if` is a far weaker signal than a `switch` over a sealed type. The chain must attribute branches to **≥2 distinct from-states** (two type tests, or one plus an `else`) — one type test is a *check*, and discriminating between states is what makes it a dispatch; this is the same threshold, for the same reason, that `CarrierTransitionDetector.qualifies` applies when it wants carrier methods on two permitted subtypes. And every link must test the **same selector variable**, decided by declaration identity with the simple name as prefilter and fallback, so a method that type-tests two unrelated H values is not read as one dispatch. The `≥2` rule has a visible price, pinned by `RelayBoard.reset()`: a single type test that commits contributes no edge even when it is a real transition.
  - `chainOf` is the single decomposition, called by BOTH the detector and the extractor. A recognizer and an extractor that each decided for themselves what a chain is would eventually disagree, and the disagreement would be an edge attributed to a state the classifier never admitted.
  - Only the **head** of a chain is a producer. Every `else if` is itself a `CtIf`; emitting one producer per link would report the tail of one dispatch as a second dispatch and walk the same branches once per link.
  - A chain inside a **lambda or anonymous class** is excluded: F7 already discovers those bodies as functional transition callables, attributes them a selector and labels them with the enclosing method's name. Same ownership rule `findCentralizedTransitionMethods` already applies to anonymous-class methods — one body, one walker.
  - `typeTestOf` flattens `&&` before looking, so the type test's position within a conjunction does not matter. Only `&&`: under `||` the branch is reachable with the test *false*, so the from-state is not determined and the condition stays an opaque guard — the same line `splitEventCondition` draws for event tests. A negated test (`!(state instanceof Init)`) attributes nothing either; it names every state but one.
- **The commit requirement IS the precision guard**, not a check bolted on afterwards. A transition switch and an exhaustive fold are structurally indistinguishable *at the switch*; only the codomain separates them. `state = switch (state)` is accepted, `label = switch (state)` yielding `String` is not, and `return switch (state)` is accepted only when the enclosing method returns H.
- The declared TYPE of the assignment target decides, never the name — two machines in one model routinely both call their field `state`. Same reasoning as `isStateFieldWrite`.
- Selector form is free: parameter, local, `this.field`, or bare field read. Spoon resolves all four to the same `CtTypeReference`, so no per-form special-casing exists (or should be added).
- The sibling-vs-nested guard is **shared** with the carrier path via `CarrierTransitionDetector.nestsHierarchyValue`. Two recognizers with two notions of "recursive data type" would eventually disagree, and the disagreement would be a false positive.

### CarrierTransitionDetector (detect/CarrierTransitionDetector.java)
Recognizes the POLYMORPHIC_CARRIER encoding and owns the **sibling-vs-nested predicate**, the precision guard that keeps the widened recognizer from swallowing recursive data types.

- `shapeOf(method, hierarchy, rootQn)` → `PEER` / `NESTED` / `NONE`. Only *returned* (or yielded) expressions count, so the void mutation encoding (F2) stays invisible here and the two paths cannot both claim a hierarchy.
- `PEER` = the H-value is terminal: returned bare, a direct argument to a shallow carrier, or `this`. `NESTED` = the H-value takes another H-value as a construction argument (composition/tree building).
- `nestsHierarchyValue(value, hierarchy)` is the single-value form of the predicate, shared with `DispatchCommitDetector`. Only a **`CtConstructorCall`** counts as the nesting node, and that restriction is load-bearing: `case Idle s -> fromIdle(s, event)` — the ordinary way a large centralized switch is factored — puts an H value in the argument list of an H-returning *call*, which is delegation, not composition. Treating an invocation as a nesting node vetoes every machine written that way, including the ones the predicate exists to protect.
- `composesItself(root)` is a gate on **every** acceptance path, not just the carrier one — a record component of the hierarchy type synthesises an accessor that reads exactly like a per-state transition method, so a tree builder reached the distributed recognizer just as easily. An explicit `@Fsm` marker still wins over it.
- **F20 — a state may REMEMBER its predecessor, and the veto has a bound.** `composesItself` was a whole-hierarchy verdict drawn from a single expression, and `nestsHierarchyValue` counted any H value in a constructor's argument list. `record Retrying(LcpState previous, int attempts)` is an ordinary retry/backoff state, and any producer writing `new Retrying(this, n + 1)` therefore sank the entire machine. Three narrowings, each closing a different half:
  - **Carrying the current state is not nesting.** An argument that *is* the state being succeeded — bare `this`, the dispatch selector, the type-pattern binding of the arm or chain link that matched — is skipped. Structural recursion *descends into* its argument's parts and so never passes the argument whole; a node containing itself is not a smaller problem. Only that whole-value case is skipped: a **part** of the current state (`this.left`, `n.operand()`) is exactly what a tree rewrite passes and still nests. The binding is found by walking OUT to the enclosing executable, because the arm that matched the from-state need not be the innermost one — `case Waiting w -> switch (tick) { case MISS -> new Waiting(w, ...) }` reads the outer arm's binding from inside an inner switch over the event. Matched on declaration identity with the name as prefilter and as the fallback when Spoon binds nothing, the F13 rule, for the F13 reason.
  - **A receiver is not an argument.** `containsHierarchyValue` flat-scanned the argument's subtree, so `r.attempts() + 1` — an `int`, whose only H-typed node is the *receiver* — reported the whole argument as a hierarchy value. Every payload computed from the current state read as composition. A receiver whose own result is in H (`n.operand()`) still nests: it is caught as the argument it is, one level up.
  - **The hierarchy-wide veto needs hierarchy-wide evidence.** It now fires on one **self-composing** production (a surviving nested argument *derived from* the current state — `new Neg(operand.simplify().result())`, which is structural recursion by definition and sufficient alone) OR on **≥2 nested productions across ≥2 distinct members**. The self-composition disjunct is not optional: a bare count threshold accepts a two-member tree whose single recursive member rebuilds itself, which is the commonest recursive sealed type in Java. A lone non-self-composing production is downgraded by the extractor to a per-edge unresolved with a note — recorded, never a verdict about the type, never silently dropped.
- `composesFromOwnParts` is the self-composition predicate, and like `nestsHierarchyValue` it is **shared** with `DispatchCommitDetector`'s switch and chain forms. Both of those apply the identical bound (one self-composing arm, or ≥2 nested arms), so a rewrite is judged the same whichever idiom spells it. Discarding a `DispatchCommitDetector` producer costs the hierarchy its only transition function where no other recognizer overlaps, which is why a single nested expression must not be able to do it.
- `findCarrierTransitionMethods` admits a `NESTED`-shaped method too. Excluding it made one compositional expression delete every **peer** edge the same method produced — the unbounded veto one level down, and a silent drop.
- `qualifies(root)` additionally requires carrier methods on ≥2 permitted subtypes and ≥1 cross-state production.
- Discovery is by shape only — never by the name `on` or the type `Transition`. `consistentMethodName()` is a reported signal, never load-bearing.

### TransitionExtractor (extract/TransitionExtractor.java)
Most Spoon-version-sensitive file. Pattern-matching switch case handling is fully reflective (`patternType()` uses `tryMethod` chains). Switch arms are read via `caseValueExpressions()` which handles block+yield, return, and arrow-expression forms.

`extract` obtains its sites from `DispatchFinder` **once** and iterates them, routing each through `walkAt(site, route, commit, walk)`. The extractor therefore no longer runs recognizers of its own, and its notion of "a transition method" cannot drift from the classifier's — they read the same list.

The per-locus walk procedures are deliberately **kept**, and they are not four spellings of one walk: `walkCarrier` does not fold inter-procedurally (that is the `POLY_CARRIER` scope line), `walkTypeChain` must thread a residual across links because the `else` has to know which states are left, and `walkFunctional` carries a from-*set* rather than a from-state. Merging them yields one walker with four flags, which is the arrangement the site abstraction removed. What the sites buy is that each walker is now selected by **data** rather than by a hard-coded pairing.

The carrier path (`extractCarrier` → `walkCarrier` → `handleCarrierValue`) runs whenever a per-state method returns a *non-hierarchy* carrier — not only when the other lists are empty, so one stray H-returning method (a helper, a record accessor) cannot silently sink every carrier edge. Methods returning the hierarchy type are skipped there; the distributed walker owns those, so the two paths never share a body.

The F2 mutation fallback runs when nothing else was found **or when every producer found was a `MUTATOR_ARGUMENT` one**, skipping hosts a dispatch already walked. The second disjunct is not a convenience: the fallback is the only thing that records a mutation commit no dispatch claimed, and once a mutator dispatch became a producer the plain guard skipped it — taking `examples/mutatorshape`'s `Vent` from an honest 1/2 to a clean-looking 1/1 with the gap deleted.

A `CARRIER_RETURN` produced value is unwrapped through `handleCarrierValue` — the same one-level rule, shared rather than restated — and **the unwrap sits BELOW the inter-procedural fold**. That order is load-bearing: above it, `case Initial i -> fromInitial(event)` is a call whose type is the carrier, so unwrapping first finds no hierarchy-typed argument in `(event)` and records a gap for every arm on a machine whose whole relation lives in its helpers. `examples/lcp_automation_chatgpt` scores 0/10 spelled that way and 111/111 spelled this way.
- from-state = the declaring class (exact, no data-flow needed — never `<unknown>`).
- targets = hierarchy-typed *direct* arguments of the carrier call, ONE level deep. Anything else is UNRESOLVED.
- The `POLY_CARRIER` commit disables F3 inter-procedural folding: that encoding is strictly intra-procedural, so `Transition.to(helper())` is recorded unresolved rather than chased. It is keyed on `POLY_CARRIER` and **not** on "any carrier": the bound was a statement about the `walkCarrier` PATH, which never had a fold to disable, and exporting it to a centralized locus would mean the same source, refactored in nothing but its return type, loses its entire relation. A `CARRIER_RETURN` dispatch therefore DOES fold, which is what takes `examples/lcp_automation_chatgpt` from 0/10 to 111/111.
- There is no `carrierMode`/`mutationMode` field any more. Both were **modes on the walker** — a caller set one, walked, and cleared it in a `finally`, and every predicate reading them was really asking "which recognizer am I running for?". That is now a `WalkSite(route, locus, commit)` set from the site being walked, read through `commitsThroughCarrier()` and `inMutationFallback()`, so the claim and the body cannot come apart and no mode can be left set across a site. `route` is not redundant with `locus`: the F2 mutation fallback has no locus at all (it is a scan, not a discrimination), and it is the route rather than the commit form that licenses reading a state-field write as a produced successor.
- `splitEventCondition` separates event tests from the data guard: `event instanceof SegmentArrival seg && seg.rst()` → event `SegmentArrival`, guard `seg.rst()`. A disjunction of pure event tests fires one edge per symbol.
- Σ expands enum members of a sealed event type into constants (`UserCall.CLOSE`), the granularity guards actually test. Labels are looked up in `eventSymbolByConstant`, built while Σ is enumerated, so an edge label and Σ cannot drift apart.
- Σ also expands an event member that **carries** an enum (`record Send(Signal signal)`) into the pair: `{Send.HEADERS, Send.PUSH_PROMISE, ...}`. One input is the pair, not the record. This is what makes `Send(HEADERS)` and a flat `SEND_HEADERS` constant yield the same |Σ| — see the two http2 fixtures. `soleEnumComponent` requires **exactly one** enum component; several is ambiguous, so Σ stays at the bare member rather than guessing which one discriminates. `composedSymbol()` is the single place the `Prefix.CONSTANT` spelling is defined, used by both Σ enumeration and edge labelling, and `componentEventNames` additionally refuses to emit a label Σ does not already contain — Σ is the authority.
- A `default` arm inside a component switch inherits the bare family label (`Send`), which reads as "that event with any component the labelled arms did not name". That is a partially-specified label and deliberately not a Σ symbol.
**F17 — a type test SELECTS the from-state; it is not a guard.** `walk` read every `if` as a condition, so a chain's type test both lost the source state and decorated the edge with what is really its own arm label. Recognition was never the whole gap: `examples/chaindispatch`'s `ShutterLogic` was accepted by the signature recognizer all along and still reported 5 edges with `<unknown>`/`<entry>` sources and 0 resolved. `walk` now handles a chain **as a unit** (`walkTypeChain`), because the `else` branch has to know which states are left:
- each link's branch is walked under the state it tests for, and the type test is consumed, never re-emitted as a guard;
- whatever else the link's condition tests still counts, split into a Σ label and a data guard by the same `splitEventCondition` the carrier walk uses — so `if (s instanceof Shut && e == OPEN)` yields `Shut --OPEN--> ...` rather than one edge labelled with a predicate;
- `chainResidual` decides the `else`: a link testing `s instanceof T` **bare** removes T outright, a link testing `s instanceof T && extra` does **not** — its branch is skipped whenever `extra` is false, so T is still reachable below, under `!extra`. Dropping T there deletes a real edge; keeping it without the negation reports a conditional edge as unconditional. The negation is of the source condition, never of the Σ symbols it split into: a symbol is a label, not an expression, and `!(LOWER)` in an SCXML `cond` is not a predicate.
- `walkBlock` threads the same residual across siblings. A chain whose links **all** terminate and which has no `else` leaves exactly the untested states reaching the next statement, so a trailing `return current;` is a self-loop on each of them rather than an `<unknown>` origin — the closed-world reasoning of the `permits` clause. An empty residual means nothing below is reachable in any state.
- The chain's `else` is **not** flagged `otherwise`, though it is the default branch: `walkSwitch` does not flag a `default` arm either, and a rule holding for one spelling of the default and not the other would put the difference between two idioms into the model.
- `extractCentralized` threads the host's hierarchy-typed parameter as the selector, which is what makes the above apply to a method the signature recognizer found. A switch-dispatched body sets no type test on the selector, so nothing changes for one — the whole corpus is byte-identical across this change.
- **A chain commits inside each branch**, unlike a switch, whose whole result is committed in one place the detector already identified. So within a dispatch recognised as `FIELD_MUTATION`, an assignment to an H-typed target IS the produced successor (`DispatchCommitDetector.isCommitTarget`, asked rather than re-derived). Restricted to `FIELD_MUTATION` deliberately: a `LOCAL_ACCUMULATOR` is read back later in the same body and F1's reaching-definitions resolves it there, so honouring the write as well would report one successor twice.

`extractCommitDispatch(producer)` is the widened centralized path: it enumerates Σ from the host's event parameter, then calls `walkSwitch` on the producer's dispatch node **only**. Hosts already walked by the signature-based recognizer are skipped (keyed on `declaringType#signature`, not a bare signature) so no body is walked twice.
- `caseEventNames(c)` returns **all** labels of an arm, so `case SEND_RST_STREAM, RECV_RST_STREAM ->` is two edges rather than one. It checks the **enum-constant case first, and that order is load-bearing**: a constant read carries the enum's own type, so asking `patternType` first answers "the event type" — labelling every arm of `switch (event)` with the enum's name and collapsing the whole alphabet to a single symbol.
- **Component dispatch** is the third switch kind, one level below event dispatch. When an event arm deconstructs its event (`case Send(Signal s) ->`) and its body switches on the binding, `componentEvent` carries the family prefix into that inner switch and `componentEventNames` composes `Send` + `HEADERS` → `Send.HEADERS`. Matching is by the binding's **name AND enum type together** — a record-pattern binding has no resolvable declaration in the Spoon model (`getDeclaration()` is `null`), so identity comparison is unavailable and the name alone would claim an unrelated switch reusing a one-letter variable.
- `dispatchedStates` records which states an arm (or a per-state method) selected. A state in that set with no outbound edge is genuinely absorbing; a state outside it has no edges only because none were recovered. `StateMachine.markTerminalStates` refuses to promote the latter — otherwise "terminal" would dress a recall gap as a result.
- **F12 — a guarded arm excludes the arms below it.** Arm order is part of the semantics: in `case Timeout t when g -> A;` followed by `case Timeout t -> B;`, the second runs only when `!g`, so the two can never both be enabled. Recording the fall-through arm as unguarded made `GuardAnalysis` report nondeterminism the source does not contain — 14 warnings on `examples/lcp_automation` for a deterministic automaton, and a wrong *claim* on `examples/dhcp-client-claude`, where `Requesting --AckReceived--> Bound` read as unconditional when it fires only if the duplicate-address check passed. `walkSwitch`/`walkCarrierSwitch` thread `priorExclusion(...)`, conjoining the negated guards of earlier arms **carrying the same label** — different labels are already disjoint, and negating those would bury every edge under redundant `!(event instanceof X)` clauses. The rule is confined to sibling arms of one switch; `examples/nondeterministic` overlaps by *semantics* (`coins >= 1` vs `coins > 0`, two separate assignments that nothing orders) and must still warn, which is the control that keeps this from becoming a blanket silencer.
  - Half of the same finding: Spoon 10.4.2 fills `CtCase.getGuard()` **only when the guard is a `CtBinaryOperator`**. For a bare invocation (`when r.acceptable()`), a unary (`when !r.catastrophic()`) or a parenthesised invocation it leaves the slot null and *prepends the guard expression into the arm body as a statement*. `leakedGuard(c)` recovers it, keyed on the **ARROW** case kind — exact, not a guess: JLS §14.11.1 gives an arrow arm a single expression, block or `throw`, so two statements there is always the leak. The kind check is load-bearing: a COLON arm holds a statement list, and `case X: helper(); return 1;` puts an ordinary boolean call exactly where a naive "first boolean statement is the guard" rule would swallow it.
- **F10 — an expression statement is not a produced successor.** Every call site of `walk` passes a *statement*, so its final `CtExpression` fallback only ever saw an expression statement — whose value Java discards (JLS §14.8). A discarded value cannot be a committed successor, so this is **exact, not heuristic**, and sits beside F9 on the compiler-checked side of the line. Unnarrowed it turned ordinary bookkeeping into transitions: `Objects.requireNonNull(event, ...)`, `log.debug(...)`, a counter bump — inflating the denominator and, where the expression was hierarchy-typed, risking a fabricated *resolved* edge. A statement that genuinely IS the commit is already claimed by its own branch (state-field assignment, or a recognised mutator call), so the rule is "ignore expression statements **that no commit form claims**", never "ignore expression statements" — `examples/plumbing-mutation` is the control that pins the difference. A hierarchy-type guard alone is NOT sufficient: `Objects.requireNonNull(currentState, ...)` is typed as H. The fallback is kept, narrowed to `isSwitchExpressionArm(...)`, because Spoon's arm modelling could change when the version is bumped.
  - Second half: Spoon wraps the arrow arm of a switch **statement** in a synthetic `CtYieldStatement`, though `yield` is illegal outside a switch expression. Walking it as a yield read a discarded value as a produced one, so `case X -> ctx.setState(new A())` never reached the F2 mutator branch and its edges were **lost** to `-> ?`. Any yield directly under a `CtSwitch` is synthetic and is unwrapped back to a statement; inside an arm's *block* a yield is always genuine, so this is a one-level rule.
- `throw` arms (including `default -> throw`) produce **no edge**: `CtThrow` is not a `CtExpression`, so `walk` skips it, and the thrown-exception helper is never mined for a successor. This is the D3 behaviour and it is pinned by test, not merely emergent.
- **F14 — a branch that leaves by `throw` does not fall through.** `alwaysTerminates` decides two things: whether the negated condition of an `if` with no `else` guards its later siblings, and whether those siblings are walked at all. It answered from `return`/`yield` alone, so `if (bad) throw new IllegalStateException(); yield new A();` — the ordinary way an arm *rejects* an input rather than ignoring it — reported `A` as **unconditional**. The guard reaches the SCXML `cond` attribute and `GuardAnalysis`, so a guard weaker than the code is a silent precision loss in a dimension the thesis reports on. The predicate is now the JLS §14.22 "cannot complete normally" question: `throw`, `break` and `continue` join `return`/`yield`, and a `CtSwitch` qualifies when it is **exhaustive**, contains **no `break`**, and **every arm terminates** — all three, because dropping any one turns the rule into a fabrication. Exhaustiveness is taken only from a `default` arm or a pattern label (JLS §14.11.2 requires an *enhanced* switch statement to be exhaustive); an enum switch with no `default` is a legacy switch and answers "no" even when it happens to cover its constants. The synthetic `CtYieldStatement` Spoon wraps a switch-**statement** arm in (see F10) is *not* a terminator there — it stands for a discarded expression, which completes normally. Both directions of a wrong answer bite, which is why `examples/throwguards` carries two negative controls: a branch that only *contains* a throw would fabricate a guard the source does not impose, and a switch left by `break` would write off the live producer after it as unreachable and **lose the edge**.
- **F9 — a helper that cannot return normally is not a producer.** `default -> reject(s, e)`, where `reject` returns H but always throws, is the same rejection as `default -> throw reject(s, e)` with the `throw` moved one call deep. `neverReturnsNormally(callee)` suppresses the edge entirely, so the two spellings report the same relation. The rule is **exact, not heuristic**, and that is the only reason it is permitted to suppress: JLS §8.4.7 forbids a non-void method whose body can complete normally, and the callee's return type is already known to be in H, so a body with no `return` anywhere provably cannot yield a successor. It sits on the compiler-checked side of the thesis's epistemic line, alongside state enumeration — not on the approximate data-flow side. Suppressed arms are counted and reported as a diagnostic, so they are reclassified rather than silently dropped. The check must run **before** the `ownedReturns(...).isEmpty()` test: both fire on a body with no reachable return but they mean opposite things — "there is no target" versus "there is a target we could not see". The scan is whole-body and unfiltered, so a `return` inside a lambda counts as the method's own; that is the conservative direction (decline to suppress).
- **F11 — F9 may only judge a body it actually read.** For a method outside the source set Spoon supplies a reflective *shadow* declaration: a real signature with an empty `{ }` body. It has no `return` because it was never parsed, so the emptiness carries no information — yet `neverReturnsNormally` read it as proof and deleted the edge. That silently swallowed every library call returning H (`Objects.requireNonNull(state, ...)`, `Optional.orElse(new Closed())`, `map.getOrDefault(k, new Idle())`): a false drop with **no unresolved marker**, the one outcome the invariant forbids. `isShadow(...)` checks `CtShadowable.isShadow()` and an invalid source position, and answers "shadow" when unreadable — declining to apply F9 is the direction that cannot drop a transition.
- **F18 — the inter-procedural fold reuses `walk`; there is no second walker.** `resolveInterprocedural` summarised a callee with `collectReturns`, a private traversal that descended blocks and `if`s and nothing else. A helper whose returns sat inside a `switch`, a loop or a `try` was therefore not summarisable — and `private H fromIdle(E e) { switch (e) { case START: return ...; } }` is the ordinary way a per-event table is factored, not an exotic shape. Two walkers over one construct is the arrangement this codebase refuses elsewhere (one `chainOf`, one commit predicate), and the cost here was the usual one: the weaker walker knew nothing of case labels, F12 arm exclusion, F10's synthetic yields or F6's exceptional flow, all of which a folded body now gets for free.
  - **Completeness is asked, not assumed** — this is the half that makes it a soundness fix. The old summarisability test was `returns.isEmpty()`, which detects a summary that failed ENTIRELY and says nothing about one that reached some returns and missed others. A partial summary was folded and published as fact: `for (...) { if (bad) return new Halted(); } return new Running();` reported a resolved self-loop and **dropped** the `Halted` target, with no unresolved marker, behind a clean-looking n/n — the one outcome the record-everything invariant forbids. `ownedReturns(callee)` enumerates the returns a call can yield; `walk` records each one it reaches (`accountedReturns`); every return left over is emitted as an unresolved transition naming the statement, and counted in a diagnostic. The set is **identity**-keyed for the same reason F13's `==` is: Spoon gives `CtElement` deep structural equality, so two arms both spelling `return new Armed();` compare equal and one would silently stand in for the other.
  - A return belongs to the callee only when `getParent(CtExecutable.class)` **is** the callee. A `return` inside a lambda is that body's exit, so counting it would report a gap on every helper that uses a stream. F9's own scan is deliberately unfiltered for the opposite reason — there, a lambda's return makes it DECLINE to suppress, which is the safe direction.
  - `markUnreachable` is the other half of the accounting: a return inside a branch the walk **proved dead** was not missed, and reporting it as a gap would invent one. Two places skip a branch on that basis — a switch arm for a state the selector provably is not, and a chain link testing an excluded type.
  - **A state switch inside a folded body is context-sensitive.** `walkSwitch` re-discriminates a value whose type the caller already proved, so when it is entered with `from` known, arms for other states are skipped and a `default` arm covers only the residual. Without it, folding any state-switching helper emits a second edge sourced at `<unknown>`. The filtering is inert when `from` is null, which is every top-level dispatch — the whole corpus is byte-identical across this change except the two fixtures that own it.
- **F20 — a composed node is not a successor, and one of them is not a verdict.** `handleValue` is the single resolution choke point, so the bounded veto's remainder is caught there: a produced value that still nests a hierarchy value is emitted as an UNRESOLVED transition whose note says why, and counted in a diagnostic. The from-state is known — it is the *target* whose relationship to it is containment rather than succession — so this narrows a claim rather than losing an edge. `examples/retrystate`'s `Frame` is the control: the composing edge is unresolved AND the other two members still resolve, which is what makes this a downgrade instead of the old whole-hierarchy loss.
- **F21 — F9 belongs at the carrier path too; the fold is not where it lives.** `illegal(new Closed(), event)` is syntactically identical to `Transition.to(new Closed(), ...)` — both are calls whose own type is outside H, carrying an H-typed argument — and `handleCarrierValue`'s one-level unwrap reads the argument of either as the successor. Nothing in the expression separates them; only the callee's body does. F9 is the instrument that reads it, but it was reachable only through `resolveInterprocedural`, which returned early for any carrier commit (then a `carrierMode` flag, now the `POLY_CARRIER` commit form). **That early return is right about folding and wrong as a hiding place.** The carrier scope line bounds *approximation*: a successor COMPUTED inside a helper stays unresolved rather than being chased. F9 computes nothing and chases nothing — it observes, from a fact the compiler has already checked (JLS §8.4.7), that there is no successor, which is why CLAUDE.md files it on the exact side of the epistemic line alongside state enumeration. So the carrier path had no F9 at all, and every specification-undefined cell became a **resolved** edge: the one failure mode the soundness invariant forbids outright, wearing a clean n/n. The commonest spelling is `illegal(this, e)`, which makes the fabrication a self-loop, one per cell — roughly forty on RFC 1661's LCP, inflating numerator and denominator together.
  - `callsNonReturningHelper` asks the SAME predicate at `handleCarrierValue`'s entry, and the suppressed calls join the same diagnostic. Sharing rather than restating is what makes F11 protection automatic here, and `examples/throwcarrier`'s `Hoist` is what keeps that honest: it is the standing probe that an unread (shadow) body is never read as proof, and it is sharper on this path than centrally, because a carrier is any wrapper at all and `Optional.of(...)` is an ordinary input.
  - Restricted to a `CtInvocation` with a `CtMethod` declaration. A **constructor** contains no `return` for a purely grammatical reason, so admitting one would suppress every construction in the corpus — the type of `neverReturnsNormally`'s parameter and `calleeMethod`'s null answer already enforce it, and both are load-bearing rather than incidental.
  - `neverReturnsNormally` now checks **non-voidness itself** instead of leaving it to the caller. That is the JLS licence's precondition: a `void` method completes normally by falling off the end, so an empty one proves the opposite of what the predicate reports. The fold established the point incidentally (it had already required the return type to be in H); the carrier caller has not, and a predicate whose exactness depends on which site invokes it is one waiting to be misused.
- **F22 — a name corroborates; it never recognises.** Two hard-coded word lists sat inside the analyzer and contradicted the contract `CarrierTransitionDetector` states in its own javadoc ("nothing keys off the name … discovery is purely by shape"). Both could not be true, and both lists failed in the direction that **fabricates**.
  - **The mutator half.** `findMutatorNames` admitted a method on either of two grounds: it assigned a state field, **or** its name was one of `setState`/`changeState`/`transitionTo`/`goTo`/`setCurrent`/`become`. An admitted method has its call sites' *argument* published as the committed successor, so `void become(Bolt observed) { this.log = observed.toString(); }` — an audit hook that commits nothing — turned every `become(current)` in the model into a **resolved** self-loop, and with it a nondeterminism warning about a deterministic machine. Recognition is now `findMutators`, structural end to end: exactly one parameter, its type in H, and a body that assigns an H-typed field an expression in which *that parameter is the only hierarchy value*.
  - **The second clause is not decoration, and it is the half the obvious fix misses.** "One H-typed parameter whose body writes an H-typed field" admits `void restart(Vent previous) { audit(previous); this.state = new Sealed(); }` exactly as the word list did — and its parameter is the state being *left*, while the successor is chosen by the callee. What licenses reading a call's argument as the target is that the mutator commits **what it was handed**; `commitsFrom` is that predicate. Only hierarchy-typed *leaves* are counted (constructions, variable and field reads), never an enclosing invocation — otherwise `this.state = Objects.requireNonNull(next)` is rejected and every call site of a defensive mutator loses its edge **silently**, because F10 ignores an expression statement no commit form claims and there is no unresolved marker to notice. An excluded look-alike is not lost: it stops being a mutator, so `findMutationMethods` walks it and the successor it really installs is recorded without a source, and the exclusion is reported.
  - **The call site is matched on the DECLARATION.** `isMutatorCall` keys on `declaringType#signature`, the same key hosts are deduped on, so the recognizer and the matcher cannot grow two notions of "mutator"; the simple name is a prefilter that keeps the lookup off unrelated calls. The fallback beneath it — `return true` on a name match whenever the callee's parameter list came back empty — is gone. That condition holds both for an unresolvable reference and for a genuinely zero-argument method, and it published an argument as a resolved successor on the strength of a word. When Spoon binds nothing the question is answered from the call's own shape (one argument, hierarchy-typed) and the call is **reported**.
  - **The labelling half.** `eventName` elided a list of English words held to be "neutral" (`next`, `transition`, `step`, `advance`, `tick`). Vocabulary is not a property of the program, and the corpus proved it: neither `on` nor `wrap` was on the list, so every edge of `retrystate`'s two machines carried the transition *function's* name as its event while the real input (`Signal.START`) sat in the guard beside it. The structural question was in the model all along — **does the name discriminate?** A hierarchy whose states all override one method has named the function, and that one name is a constant across every edge; a hierarchy exposing several (`coin()` beside `push()`) makes the choice of method the input. The rule is therefore `|{names}| ≥ 2`, decided once per hierarchy in `extract` over the methods each walk will own, and applied identically to the F7 functional callables via their supplying methods — which is what keeps `examples/cancellation`'s `add`/`subscribe` labels while dropping `retrystate`'s. `traffic` is unchanged, and it is the one answer the word list happened to get right.
- `otherwisePath` marks edges reached via an `else`, a `default` arm, or a statement following a conditional. Such an edge with **no event** is the state's default transition and is flagged `Transition.isOtherwise()` — rendered as `otherwise` in DOT and as a commented eventless `<transition>` in SCXML. It distinguishes "fires when nothing else does" from "no event was recovered". Currently set only by the carrier walk; `emit()` handles the flag generically, so extending it to the centralized walk is a one-line change (it would alter existing reference output, hence not done).

### TransitionResolver (extract/TransitionResolver.java)
The **successor sub-procedure** — one uniform mapping from a produced expression to permitted subtype(s), run identically under either dispatch encoding. Takes `hierarchyQualifiedNames` AND `rootQualifiedName`.

Resolution order in `fromVariable`, and *the order is load-bearing*:
1. **Enum constant** of a permitted enum → the constant (not the enum type).
2. **Initializer** → resolved recursively, cycle-guarded. Must come before the declared-type rules: `static final Signal INSTANCE = new Idle();` is declared as the abstract root, and rule 4 would otherwise call it a self-loop.
3. **Concrete declared type** → that state.
4. **Root-typed selector** → self-loop. Restricted to parameters and pattern bindings; a root-typed *local or field* is a value with its own identity, so it goes unresolved rather than fabricating a self-loop.

Each resolved candidate carries a `SuccessorForm` (CONSTRUCTION / SINGLETON_FIELD / ENUM_CONSTANT / SELF / LOCAL_VARIABLE / CAST), aggregated onto the machine.

- **F13 — `isReassigned` asks about a VARIABLE, not about a name.** Rules 2 and 4 both hold only for a variable this method does not write, so the gate is `isReassigned`. It scanned the declaring method for an assignment whose target *simple name* matched — which answers a question about the spelling. Java scopes a local to its block, so one method may legally declare the same name in any number of disjoint blocks, and a centralized dispatch is exactly where that happens: every arm is its own block and every arm wants to call its successor `next`. One arm's accumulator therefore condemned every other arm's local. The cost is not only the successor form (a degraded read is resolved by the extractor's reaching-definitions pass, which reports the initializer's CONSTRUCTION and drops LOCAL_VARIABLE off the axis) — that pass models only blocks and `if`s, so wherever the read sits under a `try` or a loop it bails and the edge is **lost to `-> ?`**, a real transition dropped because of an unrelated variable's name. A write is now matched on its **declaration, by identity**. The `==` is load-bearing and `equals` is unusable: Spoon gives `CtElement` deep structural equality, so two disjoint arms both declaring `Gate next = new Ajar();` compare equal — precisely the confusion being removed. The name survives as a **prefilter** only (a differently-named write can never be this variable, and it keeps the declaration lookup off every unrelated assignment). When Spoon cannot bind a same-named write to any declaration, identity is undecidable and the answer falls back to the name, taken as *reassigned* — the direction that costs a resolvable read rather than inventing an unresolvable one — and reported as a diagnostic naming the variable, so a name match never passes for a proof. The extractor's own reaching-definitions pass (`writesTo` / `writesSomewhere` / `transfer`) still keys on the name, and that is sound where it runs: it is flow-sensitive within one declaring block, where Java forbids a local shadowing a local.

### The three axes — keep them apart
Reporting is stratified along three independent axes. Collapsing any two of them reports the same recognizer capability twice and makes a recall gap unattributable.

| axis | question | values |
|---|---|---|
| `StateMachine.Encoding` | where does dispatch **live**? | `POLYMORPHIC`, `CENTRALIZED_DISPATCH` (+ `MIXED`) |
| `SuccessorForm` | how is the successor **spelled**? | CONSTRUCTION / SINGLETON_FIELD / ENUM_CONSTANT / SELF / LOCAL_VARIABLE / CAST |
| `CommitForm` | how is the successor **installed**? | VALUE_RETURN / FIELD_MUTATION / LOCAL_ACCUMULATOR / POLY_CARRIER / CARRIER_RETURN / MUTATOR_ARGUMENT |

(On the `unresolved-member-recovery` branch, `State.isDeclarationUnread()` is deliberately **not** a fourth axis. The three axes classify how a machine is *written*; that flag records how much of it the tool was allowed to *read*, which is a property of the invocation and not of the program. Stratify by it if you like, but never fold it into these.)

A carrier-returning per-state method is `POLYMORPHIC` dispatch with a `POLY_CARRIER` commit — not an encoding of its own. `return switch (s)` and `this.f = switch (this.f)` are the same encoding with different commits.

`DispatchLocus` is a **fourth, finer** classification of the first axis and is deliberately NOT a fourth axis: four loci map onto the two `Encoding` positions via `DispatchLocus.encoding()`, because a `switch` and an `instanceof` chain are one dispatch written two ways. It is not in the output today; exposing it is a reporting change, and the mapping already exists.

`POLY_CARRIER` and `CARRIER_RETURN` are **one commit mechanism at two loci** — the first at `POLYMORPHIC_OVERRIDE`, the second everywhere else. They are separate enum values purely for continuity with the published stratified table; collapsing them is a one-line change plus a re-baseline. `MUTATOR_ARGUMENT` was split OUT of `FIELD_MUTATION` for the opposite reason, and that split is real: a field write is a commit the analysis SEES, while a mutator argument additionally rests on a structural reading of the callee's body, so pooling them reported an observation and an inference under one label and made a gap in the inference unattributable.

**Every `(DispatchLocus × CommitForm)` pair is enumerated in `FIXLOG.md`** — reachable-and-exercised, reachable-but-untested, or not reachable, with the fixture or the reason for each. That table is the map of what the recognizers can and cannot see.

### Composite states (both serializers)
A composite state is a permitted subtype that is itself sealed, **or an enum** (its constants become children). `topLevelStates()` is exactly the `permits` clause; `allStates()` is the flattened count the summary prints — so `Signal` reports 6 states for a 4-member `permits` clause, and that is correct, not a miscount.

Two things composites break if handled naively:
- **DOT**: `cluster_X` is not a node. Naming it in an edge makes Graphviz invent a second node with the same label, so the diagram shows the state twice. Edges touching a composite attach to an invisible `__anchor_X` inside the cluster and clip with `lhead`/`ltail` (needs `compound=true`). Clipping is suppressed when both ends are inside the same cluster — Graphviz warns and ignores it there.
- **SCXML**: a self-transition on a composite with a `target` *exits and re-enters*, landing on the initial child. A `stay(this)` self-loop must be emitted **without a target** (internal transition) or a machine in PEAK silently jumps to RAMP.

Verify renders with `dot -Tsvg out/X.dot -o /dev/null` — it must print no warnings.

### ScxmlSerializer (serialize/ScxmlSerializer.java)
Transitions are emitted inside the `<state>` matching their source id, so anything sourced at a **pseudo-state** needs `emitPseudoStates`:
- machine entry (`<initial>`) becomes a real `<state id="_initial">`, because the document's `initial` attribute must resolve to a declared element;
- an undetermined source (`<unknown>`/`<entry>`) becomes a trailing comment — it is a gap, not a state, and inventing a `<state>` for it would put a fiction in the model.

`scxmlId()` maps `<initial>` → `_initial`: the raw form is not a legal XML name. Every emitted `initial`/`target` must resolve to a declared `<state>` — losing an edge here would break the "unresolved transitions are never dropped" invariant silently, since DOT would still show it.

A terminal **leaf** is emitted as `<final>`, SCXML's spelling of an absorbing state; DOT gives it `peripheries=2`. A composite is never emitted as `<final>` even when nothing leaves it — `<final>` may hold no children, so doing so would delete part of the machine from the document.

### Analyzer (Analyzer.java)
Initial-state heuristics (priority order). **No rule picks between rival candidates** — a model is a set of files with no meaningful order, so "the first one found" is a claim about which file Spoon walked first dressed up as a claim about the program. Rules 1 and 3 both collect every candidate and answer only when they are unanimous; a disagreement is reported and falls through. A machine with no initial state reports a gap, whereas a wrong one is a fabricated claim.
1. A field typed as the hierarchy initialized with `new Concrete()` (e.g. `private TrafficLight current = new Red()`), and only when every such field agrees. Unanimity here is **F15** and was the last rule missing it: `return`ing the first field found meant two drivers seeded from different states had the machine's start decided by filename — on `examples/rivalseeds` the old rule reported `Shut`, and renaming `PrimaryDriver` so it sorted last reported `Flowing` from byte-identical logic.
   - `isSelfSingleton` is what makes that unanimity safe, and it is **not** cosmetic: a field whose initializer constructs its own declaring type is that type's own instance, never a statement about where the machine starts. It covers two shapes, and both are in the corpus. A **flyweight** state constant (`static final Armed INSTANCE = new Armed()`) — every state may declare one, so counting them makes each state a rival candidate. And, less obviously, an **enum constant**: Spoon models `Phase.IDLE` as a `CtEnumValue extends CtField` typed `Phase` with an implicit `new Phase()` default, so every permitted enum was a candidate. Without the exclusion, unanimity *loses* correct answers — `rivalseeds.Ratchet` and `examples/namecollision` both abstain, the latter reporting `[Mode, Phase, namecollision.Idle]` disagree. Under the OLD rule `namecollision` was right only by traversal luck: rename `LinkDriver` to sort last and it reports the composite enum `Mode` as the initial state.
2. The unique state with no resolved incoming edge but ≥1 outgoing edge
3. A hierarchy-typed **local** initialized with `new Concrete()`, declared OUTSIDE the hierarchy, and only when every such local in the model agrees. The scope restriction pairs with `isSelfSingleton` on rule 1: a local inside a state class is a successor under construction (`Signal next = new Firing();` in `Armed.on`), so without it, fixing rule 1 merely moves `examples/valueforms`' fabricated answer from `Armed` to `Firing`. Deliberately last and deliberately unanimous: a local is usually a *driver's* starting point, not the machine's, so it is consulted only after both structural rules abstain and it abstains itself the moment two locals disagree. It exists because a dense automaton defeats rule 2 exactly when it is most faithful — in RFC 1661's LCP every state including `Initial` has incoming edges. When it fires, the result is reported as **weaker evidence** in a diagnostic naming what it rested on; a machine with no initial state reports a gap, whereas a wrong one is a fabricated claim.

## Coding conventions

- Java 21 features are encouraged: records, sealed types, pattern matching, `var`, text blocks.
- No Lombok, no Spring, no frameworks — this is a command-line analysis tool.
- Every Spoon API call that might differ across versions goes in `SpoonCompat`, in `detect/dispatch/CasePatterns`, or is guarded with try/catch + reflection in `TransitionExtractor`.
- Unresolved transitions are always RECORDED, never silently dropped. This is non-negotiable.
- Diagnostics (INFO/WARN) go through `ExtractionResult.info()/warn()`, not stdout. `--explain` traces go through `ExtractionResult.explain()`, a separate channel: a diagnostic reports something the analysis *found* and is suppressed by `--quiet` on that basis, whereas a trace is the decision procedure narrating itself **on request** and is printed whenever it was asked for.
- The `Main` class handles stdout; analysis code is silent.
- **One notion, one implementation.** Where two places need the same question answered — what a chain is (`chainOf`), what a commit is (`CommitClassifier`), what nests (`CompositionVeto`), what a case label matches (`CasePatterns`), how a state is named (`StateNaming`) — there is exactly one implementation and the other place calls it. A second copy drifts, and here the drift is always the same failure: an edge attributed to a state the recognizer never admitted.
- **No analysis decision keys on a method or field NAME** (F22). A transition method's name becomes an event label only when the hierarchy spells more than **one** such name — one name across every state names the transition *function* and discriminates nothing, so it produces a `null` label. There is no list of "neutral" words, and none may be reintroduced. Where a simple name survives it is a prefilter over a decision taken on a declaration or a type, and a residual name match is always reported as a diagnostic.

## v1 scope lines (what is deliberately left out)

These are acknowledged limitations, not bugs. Do not "fix" them without explicit instruction:

- Inter-procedural targets beyond the k = 2 budget (`return helper()`) → unresolved
- A **mutator-shaped method that commits something other than its argument** (`void restart(Vent previous) { this.state = new Sealed(); }`) claims none of its call sites, so the edge is attributed to no source: the commit is recovered by walking the method itself and recorded as unresolved, and the exclusion is reported. Attributing it would mean threading the call site's from-state into the callee, which is inter-procedural, and the F2 path is not. `examples/mutatorshape`'s `Vent` pins the cost — 1/2 where the fabrication scored 2/2
- A folded helper's return that `walk` does not descend to — today only one inside a `synchronized` block — stays unresolved and is reported. This is a boundary of the walker, not of the fold: extend `walk` and the fold follows, which is why `examples/hiddenreturns` pins it as a probe rather than as a rule
- Centralized-style event labelling from method names → future work
- Multi-file scattered hierarchies → Spoon handles if given all source dirs
- Carrier arguments are descended ONE level only, and under `POLY_CARRIER` a successor computed by a helper stays unresolved (deliberate; the bound belongs to that path, not to carriers in general — a `CARRIER_RETURN` dispatch folds). A helper that provably **cannot return** is the exception and not a relaxation of it: it contributes no edge at all (F21), because the scope line bounds approximation and F9 is not one
- A type-test chain needs **two discriminated branches** and an explicit `else` for its residual. `if (s instanceof Cancelled) return s; return new Cancelled();` — one test with the fall-through acting as the else — is therefore not recognised as a producer, and a single committing type test contributes no edge at all (`examples/chaindispatch`'s `RelayBoard.reset()` pins this). Both are thresholds on how weak a signal an `if` is, not statements about the code.
- ~~A chain or switch committed through a **mutator call** is not a producer.~~ **Closed** by `CommitForm.MUTATOR_ARGUMENT`: `MutatorRecognizer` answers it structurally (one parameter typed with the hierarchy ROOT, whose value is what the body installs into an H-typed field), and `DispatchCommitDetector` asks it *after* the syntactic forms decline, so this can only add machines and never re-attribute one. Two narrowings are load-bearing and both were found by fixtures, not by inspection:
  - the parameter must be the **root**, not merely a member. A permitted subtype may itself be sealed, so H(child) ⊆ H(parent) and `setState(Body next)` sits inside the parent's hierarchy too — `examples/nestedroots` went from `Message` correctly abstaining to `Message` published as a five-state automaton with `Body` never classified;
  - the **F2 fallback must still run** when every producer found was a `MUTATOR_ARGUMENT` one (skipping hosts a dispatch already walked). It is the only thing that records a mutation commit no dispatch claimed, and skipping it took `examples/mutatorshape`'s `Vent` from an honest 1/2 to a clean-looking 1/1 with the gap deleted.
- A state that rebuilds **its own type out of its own H-typed component** — `case Retrying r -> new Retrying(r.previous(), r.attempts() + 1)` — is vetoed as structural recursion, because it is textually identical to a tree rewrite and nothing distinguishes them. The spelling that is recovered is the one that carries the state whole (`new Retrying(r, ...)`), which is also the one that actually means "remember my predecessor"; reading a predecessor back out and re-wrapping it is a fold.
- **Analysis stays intra-procedural at the dispatch.** A commit the analysis cannot see inside the host method is a commit it must not claim: `CommitClassifier.classify` consults only the switch's immediate syntactic context and never follows the value through a helper or into another object's field. `MUTATOR_ARGUMENT` is not an exception — it reads the *callee's* body to decide whether a call is a commit channel, which is a question about the callee, and it still claims nothing about where the value came from.
- **`FUNCTIONAL_CALLABLE` is still fused to `VALUE_RETURN`**, and it is fused in the EXTRACTOR rather than in the recognizer. `DispatchFinder.functionalSites` finds the locus independently and `CommitClassifier` would answer for it, but `extractFunctional` hard-codes `VALUE_RETURN` and `walkFunctional` — which carries a from-*set* rather than a from-state — only treats a returned value as a production. A lambda committing by field write or mutator call contributes nothing. Closing it means teaching `walkFunctional` the commit branches `walk` already has, over a from-set; no corpus fixture demands it.
- **The encoding axis has exactly TWO positions** — `POLYMORPHIC` (per-state dispatch) and `CENTRALIZED_DISPATCH` (one switch over H) — plus `MIXED` for "both, or undetermined". Do not add a third. Where the switch is *hosted*, how the successor is *spelled*, and how it is *committed* are sub-dimensions: a new spelling extends `SuccessorForm`, a new installation mechanism extends `CommitForm`, and neither ever extends `Encoding`.

**Analysis must be scope-isolated.** Two machines in one model must produce exactly the edges they produce alone — `ExtractionIntegrationTest.mutationMachinesDoNotAbsorbEachOthersAssignments` pins this. The F2 mutation path is the fragile one (a void mutator gives it nothing typed to anchor on), so `isStateFieldWrite`/`isMutatorCall` use the field/parameter **type** to decide and the name only to prefilter. Never relax that back to a name-only match: two machines that both call their field `state` then swallow each other's assignments. Until F22 that sentence was **false** of `isMutatorCall`, which returned `true` on a bare name match whenever the callee's parameter list came back empty — a condition that holds for an unresolvable reference *and* for a genuinely zero-argument method — and only half-true of `isStateFieldWrite`, whose unresolvable-type fallback still keeps the name match. That fallback stays, because rejecting there drops a commit with no unresolved marker; what F22 adds is that it is **reported**, so no name match anywhere in the analysis passes for a proof in silence.

## What to work on next (likely tasks)

- Expand the corpus: harvest GitHub for real sealed FSM hierarchies
- Add more example fixtures for edge cases (enum-based states, nested composites, multi-method distributed)
- Narrow the root-typed-parameter self-loop rule in `TransitionResolver` to the *actual dispatch selector*. Today `isSelectorBinding` accepts **any** parameter, so a second root-typed parameter (`H step(H current, H fallback, Event e)` returning `fallback`) resolves as a proven self-loop instead of UNRESOLVED — a fabricated resolved edge, which is the one failure mode the soundness invariant forbids. Needs a fixture with two root-typed parameters.
- Reconsider `MIXED` for `Portal` / `Vend` — **partly done, and these two are what is left**. Four other mutation machines (`plumbing-mutation.Hopper`, `nestedroots.Body`, `mutatorshape.Bolt`/`Vent`) moved off `MIXED` to `CENTRALIZED_DISPATCH` once `MUTATOR_ARGUMENT` made their dispatch a recognised one, and Portal's commit is now correctly `MUTATOR_ARGUMENT` rather than `FIELD_MUTATION`. But Portal (5 edges) and Vend (3) are still `MIXED`: their dispatch is per-state callbacks and a field-mutating driver respectively, reached through the F2 fallback, which has **no locus** — so nothing tells `detectEncoding` which position to report. Giving the fallback a locus is the fix, and it is a real modelling decision rather than a relabelling: the fallback is a scan of the methods that write the state field, not a discrimination.
- Close `FUNCTIONAL_CALLABLE × {FIELD_MUTATION, MUTATOR_ARGUMENT, CARRIER_RETURN}` — the one axis pair still fused, and the only one fused in the extractor rather than the recognizer. See the scope line above.
- `INSTANCEOF_CHAIN × LOCAL_ACCUMULATOR` is reachable (`commitFormOfChain` asks `CommitClassifier.ofTarget`, which answers `LOCAL_ACCUMULATOR` for an H-typed local) but **no fixture writes a chain that accumulates into a local**, so it is the one cell in `FIXLOG.md`'s table argued rather than measured.
- Expose `DispatchLocus` in the summary table if the validation chapter wants recall stratified by it. The mapping onto `Encoding` already exists; only the reporting is missing.
- Extend `otherwisePath` to the centralized walk (`emit()` already handles the flag generically; it would alter existing reference output)
- Write more targeted unit tests for `TransitionResolver` expression shapes
- Thesis writing: validation chapter, corpus results tables — the `CommitForm` axis is what the stratified recall table is keyed on
